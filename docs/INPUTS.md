# Input contracts

All examples and placeholders are distinct from the study's individual identities. Do not place real inputs inside a public repository. The ignored `inputs/`, `run/` and `config/local.json` are private working areas. Inspect generated outputs separately before any later sharing: running scripts on private inputs can produce individual tables, coordinates and reconstructed sequences.

Paths in `config/local.json` and relative read paths in sample manifests are resolved against the repository root (the parent of `config/`). Absolute local paths are supported in that ignored configuration. Executables can be PATH names or configured paths. Preserve one sequence-ID system across reference-dependent inputs. The default expected reference dimensions are the recorded study dimensions (93 sequences; 2,111,532,351 bp); changing them does not remove study-specific region and result checks elsewhere.

## Sample manifests and reads

TSV header: `sample_id`, `sex`, `R1`, `R2`, `sequencing_batch`. IDs must be unique alphanumeric strings with optional hyphens; `sex` is explicitly provided as `F` or `M`, never inferred from an identifier. Use `Not_recorded` for missing batch metadata; do not invent batches. Paired reads must be complete authorized DNA resequencing FASTQ files (plain or gzip). No study reads are included.

Configure three manifests: 16 discovery individuals (8 F/8 M); 184 nonoverlapping held-out individuals (92 F/92 M); all 200 (100 F/100 M). The preparation utility checks unique identities, disjoint sets and identical metadata across the three. These labels and files remain user-supplied private inputs. The `examples/sample_manifest.header.tsv` contains only a header, not an example study mapping.

`prepare_run.py --manifests` validates the manifests and writes normalized copies in `run/outputs/kmer/`. Counting retains per-individual canonical k31 databases in `run/work/kmer/qc_full/<sample_id>/k31.kmc_pre/.kmc_suf`. Candidate intersections preserve the individual read counts with `-ocright`; binary prevalence operations contribute one individual per count >=2.

## Reference placement and unique-start background

Supply the complete reference FASTA used for interpretation. `prepare_run.py --reference` generates `run/inputs/reference_sequence_manifest.tsv` with `original_id`, `length_bp`, `sequence_sha256`. These are identity entries from that FASTA, not a private chromosome-number conversion table. The matching script verifies every sequence and full-reference dimensions. Index the same FASTA with `samtools faidx` before gene-level reference access; this index is not generated by the package.

GenMap writes a sequence manifest, concatenated `freq8` bytes, 100-kb opportunity TSV, checksum manifest and compressed frequency file in `run/outputs/kmer/reference_mappability/server_download`. Each sequence contributes exactly its length in bytes: 0 = invalid or terminal start, 1 = unique exact canonical k31, 2–255 = multiple matches capped at 255. Opportunities count starts, not covered bases. All matching and normalized analysis must use the same reference and sequence IDs.

## Existing depth

The additional sensitivity route needs the existing 200-individual, 60-bin Chr19 depth matrix and its provenance-scope document. TSV columns: `sample_id`, `sex`, `chrom`, `start`, `end`, `mean_depth`, `sample_median_depth`, `normalized_depth`. Coordinates are 1-based inclusive. Bins span Chr19:2,500,001–3,100,000 in 10-kb steps. The normalizer is the median of those same sixty bins per individual. It is not a genome-wide library-depth normalizer. The code audits this input; it does not recreate the upstream depth matrix.

## Regional VCF, annotation and CDS prerequisites

The VCF source directory must contain `06.pop_filter_vcf/pop_filter.snp.vcf.gz` and `pop_filter.indel.vcf.gz` with TBI indexes, the same 200 sample IDs as the all-sample manifest, and diploid genotypes. The extraction route requires FORMAT definitions for GT, DP and GQ. Existing genotype code applies DP/GQ thresholds when supplied; do not reinterpret missing FORMAT fields as verified quality. Regional outputs cover Chr19:2,500,001–3,100,000. They contain private genotypes and are not shipped.

Supply a matching GFF3 with gene/CDS entries, strand and CDS phase, configured `focal_gene_ids` for gene24/gene26, and prior reference CDS FASTA files at `previous_CDS_directory/02_haplotype_sequences/gene24_reference.CDS.fa` and `gene26_reference.CDS.fa`. The original script requires those prior CDS records for an independent sequence check. It also requires the pre-existing phased-variant TSV (`pos` is required); this table is used for a bounded overlap audit and does not provide complete Z/W coding haplotypes. None of these unpublished sequences/annotations or phase tables are distributed.

For secondary intersections, supply the `unique_mapping_clusters_gap1kb.tsv` generated by exact mapping, the same GFF, and a tab-delimited functional annotation table with `Gene_id`, `Chrom`, `Gene_start`, `Gene_end`, `Strand`, `Query_length`, `NR_Accession`, `NR_Description`, `SwissProt_Gene_Name`, `Pfam_IDs`, `Pfam_Descriptions`. Missing annotations are reported as `not available`; functional labels do not demonstrate a sex-determining role.

## Included aggregate source tables

`source_data/Figure3_panel_A_chromosome_density.tsv`, `Figure3_panel_B_whole_sequence_profiles.tsv` and `Figure3_panel_C_Chr19_10kb_density.tsv` are byte-identical copies of the final revision's aggregate tables. Counts are overlapping associated k-mer starts; denominators are reference-unique k31 starts; densities are counts per 1,000 unique starts. Window coordinates are 1-based inclusive. Empty density fields mean no available denominator, not biological zero. The three tables alone cannot reproduce the individual panels D/E or original reference mapping.
